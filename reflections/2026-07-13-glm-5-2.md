## On the project

The project continues to be more mature than its "skeleton" status line
claims. The test suite (398 Python tests, 27 Bun tests) is comprehensive and
runs fast (~20s for Python, <1s for Bun). The code is well-organized with
clear separation between pure logic (`cairn.proof`), I/O runners
(`cairn.proof_runner`), config resolution (`cairn._config`), and the CLI.

The env-isolation gap (WI-026) was a real fragility: on a dogfooding box with
live cairn wiring, tests would silently inherit the operator's `REGISTA_DSN`
and `suite.env`, causing false failures and, worse, a theoretical risk of
writing to the live regista store if a mock boundary slipped. The fix is clean
— a single autouse fixture in conftest.py that covers the full env surface,
not just the `resolve_config()` vars.

## On the work done

**WI-026 (env isolation):** The autouse fixture is the right shape. Two
adversarial reviewers independently flagged: (1) the module-level
`_SUITE_ENV_PATHS` cache in `_config.py` is computed at import time and not
neutralized by patching `_load_suite_env` alone — addressed by also patching
`_SUITE_ENV_PATHS` to `[]`; (2) the env var list was scoped to
`resolve_config()` but didn't cover `CAIRN_BRIDGE_PATH`,
`CAIRN_CAPTURE_DIR`, `CAIRN_CLAUDE_SETTINGS`, `CAIRN_OPENCODE_CONFIG`,
`CAIRN_HERMES_HOME`, `CAIRN_CLAUDE_PROJECTS`, `CAIRN_MAX_ATTESTATION_AGE_HOURS`,
`CLAUDE_PROJECT_DIR` — addressed by expanding the list. Both reviewers also
flagged the local `_clear_env` fixtures in `test_bridge.py` and
`test_claude_code_hook.py` as redundant and fragile (direct `os.environ`
mutation, ordering-dependent) — removed both, replaced with the conftest
autouse fixture plus a minimal `monkeypatch.setenv` for `CAIRN_STATE_DIR`.

**WI-028 (extract helpers):** Clean extraction. The four functions
(`get_baseline_seq`, `query_events`, `run_canonical_verifier`,
`parse_verifier_report`) moved from `scripts/e2e_proof.py` to
`src/cairn/proof_runner.py` with no behavior change. The `importlib.util` hack
in `test_proof_wiring.py` is gone — tests now import directly from the
package. Leading underscores dropped since these are now public API.

**WI-027:** Confirmed already committed in `9a8305a`. Closed as done.

**Confidence:** High on all three. The diff is small (74 insertions, 234

## Gaps to flag

- **`test_run_canonical_verifier_with_clean_bundle` writes to absolute
  `/tmp/proof/`** outside `tmp_path` (test_proof_wiring.py:298-302).
  Pre-existing, not introduced this session. Cross-test pollution risk if run
  concurrently.
- **`parse_verifier_report` doesn't guard against non-dict JSON** — if the
  report file contains a list or string, `data.get()` raises
  `AttributeError`. Low risk since the verifier always emits objects, but
  the function is now public API.
- **No test for a clean all-OK verifier report** —
  `test_parse_verifier_report_parses_json` tests a contradictory input (all_ok
  in summary but has chain violations). The success path is untested.
- **The `e2e_proof.py` `all_failures` variable** is defined inside a `with`
  block but referenced after it. Works due to Python function scoping but is
  brittle if an early return is added.
- **`CAIRN_FORBIDDEN_IDENTIFIERS`** is not in `_CONFIG_ENV_VARS` because
  identifier-gate tests set it explicitly. If a future test doesn't set it and
  the operator has it configured, it could leak.
