# Session Reflection — 2026-05-25

**Work summary:** Adversarial security review of the cairn codebase. Found and fixed 4 issues: a resource leak in `_bridge.py` (unclosed substrate connection and `/dev/null` file handle), a missing stdin size limit allowing memory exhaustion, silent conflation of missing vs. empty files in `digest_file`, an unsanitized `session_id` enabling path traversal in the Claude Code hook, and a silent fallback in `_resolve_begin_payload` that produces unverifiable end events without warning.

---

## On the project

This is a well-structured audit provenance project with unusually clear design documentation. The README functions as an honest design doc — the scope statement (§2) is explicitly load-bearing and the trust model layers are laid out cheapest-to-most-defensive. The code is straightforward and the test coverage for the core path is solid (39 tests).

The biggest structural concern is something the README already owns: the gap between "events that reach the configured harness" and "all agent activity." The project is honest about being an audit layer, not an enforcement layer, but the code doesn't make this distinction as crisp as the prose does. The `digest_file` returning `sha256("")` for missing files (now fixed) was a concrete instance of this — an auditor couldn't tell if a file was absent or merely empty, which undermines the tamper-evidence story.

The split between `_bridge.py` (Python, stdin-driven) and `cairn_hook.py` (Python, also stdin-driven but for Claude Code) and `index.js` (TypeScript, OpenCode plugin) is functional but means three integration points to maintain. The TypeScript plugin delegates to the Python bridge, which is the right call.

## On the work done

The adversarial review found real issues:

1. **Resource leak in `_bridge.py`**: The substrate connection was created but never closed. For a bridge that runs per-tool-call via subprocess, this leaked a Postgres connection per invocation. Also leaked the `/dev/null` file handle opened at module level. Fixed by wrapping `_dispatch` in `try/finally` with `sub.close()` and `_null_fh.close()`.

2. **Unbounded stdin in `_bridge.py`**: `sys.stdin.read()` with no limit. A malicious or broken caller could pipe unlimited data and exhaust memory. Fixed with a 10 MiB cap.

3. **`digest_file` returning `sha256("")` for missing files** (`schema.py`): For an audit tool, an auditor must be able to distinguish "file was absent" (no digest recorded) from "file was present but empty" (digest of empty bytes recorded). Changed return type to `str | None`, returning `None` for missing/unreadable files. The `FileDigest` dataclass already supported `None` for `pre_digest`/`post_digest`, so callers are type-compatible.

4. **Path traversal via `session_id` in `cairn_hook.py`**: The `session_id` from hook input was used directly in path construction (`_state_dir(session_id) / ...`). A malicious session_id like `../../etc/cron.d/backdoor` would create state files outside the intended directory. Added `_safe_session_id()` that strips non-alphanumeric characters.

5. **Silent fallback in `_resolve_begin_payload`** (`adapter.py`): When the `tool_call_begin` event wasn't found, the code silently fell back to returning `"tool_args_hash": ""`, which creates end events with no verifiable link to the original args hash. Added a `log.warning` so this is at least audible in logs.

All fixes pass the existing 39 tests. No new tests were added — the `digest_file` return type change is exercised by existing tests that use in-memory substrates, and the security fixes are in error paths that require external callers.

## On what remains

- **Project registration with agent-notes-mcp** (mentioned in AGENTS.md as "not done yet"). Without this, breadcrumbs can't be filed properly.
- **Live dogfood of Claude Code hooks** — AGENTS.md says "not tested in a live Claude Code session (mock tests only)." This remains true.
- **The opencode plugin** (`integrations/opencode/index.js`) has a `sessionMap` that's in-memory only — if the process restarts, all in-flight tool calls are orphaned with no end events. This is a known limitation but worth noting.
- **Bundle export** (`cairn export`) leaks the DSN host into the manifest (`source_dsn_host`). This is intentional for auditor context, but the code doesn't redact credentials from the DSN string itself. If `--dsn` contains a password, it would be in the exported bundle's events.

## Gaps to flag

- `_bridge.py` now closes `_null_fh` on exit, but if the process is killed mid-run, the file handle leak persists. Not practical to fix for a subprocess; noting for honesty.
- `digest_file` now returns `None` for missing files, but the verifier's `_accumulate_file_provenance` reads files directly with `Path(path).read_bytes()` and catches `OSError`. The verifier's path traversal risk (event payloads containing `/etc/shadow` etc.) is not mitigated — the verifier is an offline tool reading paths from a potentially-untrusted bundle.
- `cairn_hook.py` doesn't validate that `session_id` is actually present in hook input — it falls back to `"unknown"`. The `_safe_session_id` function maps this to `"unknown"` which is fine for state files, but means all sessions with missing session_ids share state files, which could cause collisions.
- The `_call_key` function in `cairn_hook.py` uses only first 16 hex chars of SHA-256, giving ~64 bits of collision resistance. For an audit tool, this is adequate but worth noting.
- `schema.py:digest_file` catches `FileNotFoundError`, `PermissionError`, and `IsADirectoryError` but not `OSError` broadly — if a file exists but is unreadable for other OS reasons (e.g., EIO), it will raise uncaught. This is arguably correct (audit tool should surface I/O errors) but could crash a tool-call recording path.
