## On the project

The codebase is in good shape for pre-alpha. The verifier is the most
critical component and it's well-structured — the tristate pattern
(True/False/None) for bundle_hash_ok and chain_integrity_ok is clean.
The main risk is that the verifier now carries a lot of accumulated
checks (scope coverage, principal binding, temporal ordering, chain
contiguity, witness coverage, role gates) and the interaction between
them isn't always obvious. The `all_ok` property has 15 sub-conditions
and it's easy for a new check to interact unexpectedly with existing
ones.

The OpenCode plugin (index.js) is the weakest link — it's thin but has
no degradation handling for bridge failures, and the sessionMap has no
TTL. The Claude Code hook is more robust (has _mark_degraded). This
asymmetry will bite if the project moves to production.

## On the work done

The BC-012 fix (malformed timestamp) was the most satisfying — a
one-line change in the adapter plus a proper datetime-comparison helper
in the verifier. The BC-011 fix (malformed bundle handling) was
straightforward defensive coding. BC-014 (chain integrity over-claiming)
required careful thought about the tristate semantics and updating both
text and HTML formatters.

I'm confident in all four bug fixes. The scope-coverage and
principal-binding datetime comparison changes are an improvement but
I didn't add tests specifically for the datetime-parsing edge cases
(the `_parse_iso` helper). This is a gap.

## On what remains

**Needed before shipping:**
- BC-005 (scope attestation transitions) — blocked on regista Plan 016.
  Acceptable for v1 given Ed25519 signing.
- BC-016 (witness signature verification) — blocked on regista
  asymmetric witness signing. Known architectural limitation.
- New BC: temporal ordering check flags ALL events, not just
  batch-covered events. This is a real bug that can cause false
  negatives on clean bundles.
- New BC: CLI export silently swallows errors loading timestamp and
  witness data. Auditors get incomplete bundles with no indication.
- New BC: OpenCode plugin loses end events on bridge failure.

**Nice to have:**

- Test coverage for the new `_parse_iso` helper and BC-011/BC-012/BC-014
