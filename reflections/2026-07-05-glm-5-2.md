## On the project

The identifier gate is now structurally sound. The adcs-lens two-tier pattern (always-on samples guard + secret-driven identifier scan) is the right design: the always-on guard catches `git add -f` bypasses of `.gitignore`, while the secret-driven scan catches identifiers that leaked into tracked files. The denylist covers all forms: hostnames (FQDN/NetBIOS/short), AD domain, email, personal name, principal_id handles, DB service accounts. The audit script provides the dry-run report that the task asked for — it documents every leak in git history without modifying anything.

The regista repo is in much worse shape than agent-provenance: 1632 leaks in history (primarily unscrubbed author/committer identity — 402 commits with the real name and email). The agent-provenance history has 23 leaks in old reflection files, the deleted `identifier-gate.py`, and AGENTS.md. Both need a destructive `git filter-repo` pass before the public flip, but that's explicitly out of scope for this task (dry-run + report only).

## On the work done

The adversarial review caught a critical self-leaking problem: the audit report and replacements file contain the very identifiers the gate is meant to catch. If committed, they would fail the gate and re-leak the identifiers in the public repo. Fixed by gitignoring both files. The checklist was also redacted to not inline raw identifiers.

The `_SKIP_DIRS` fix was subtle: the original code skipped any path containing a `samples` component anywhere, which created a false-negative hole for nested `tests/samples/` directories. Fixed by removing `samples` from `_SKIP_DIRS` — the always-on guard already handles root-level `samples/`, and nested dirs should be scanned normally.

The `--no-renames` fix for the staged mode was important: without it, a file renamed into `samples/` via `git mv` would not trigger the local pre-commit hook because `--diff-filter=ACM` excludes renames. With `--no-renames`, the rename is decomposed into add+delete, and the new path is caught.

The `.gitignore` change from `samples/` to `/samples/` aligns git's ignoring with the guard's root-only semantics — previously, a legitimate `tests/samples/` directory would be silently gitignored.

I'm confident in the check_committed_identifiers.py changes — they're well-tested with 19 tests. I'm less confident in the audit script's coverage of edge cases (merge commits, annotated tags, dangling commits) — the reviewers flagged these as medium gaps, and I chose not to address them in this session since the audit is a dry-run tool and the main leaks are in straightforward commit diffs and identity.

## Gaps to flag

- **`docs/history-identifier-audit.md` and `scripts/filter-repo-replacements.txt` are gitignored** — they contain raw identifiers and must never be committed. The next agent should verify they're not tracked before any push.
- **`scripts/filter-repo-replacements.txt` ordering** — the replacements file lists shorter identifiers before longer ones (e.g., a short hostname before its FQDN form). `git filter-repo --replace-text` processes replacements top-to-bottom, so shorter matches could partially replace longer identifiers. Should sort longest-first before the actual scrub.
- **regista `filter-repo-replacements.txt` missing DB service accounts** — regista's replacements file doesn't include the DB service account names or principal_id handles that agent-provenance covers. These may or may not appear in regista's history (the audit only checked the 6 identifiers in regista's denylist). Should cross-check before the scrub.
- **Audit script line-number parsing** — the `@@` hunk parser is fragile for combined diffs (merge commits). Flagged by both reviewers as low severity.
- **`scan_files` has no size limit** — `path.read_text()` loads the entire file into memory. A very large tracked file could OOM. Flagged by both reviewers.
- **regista working tree has 20 identifier violations** — reflections, plans, CHANGELOG, README contain real hostnames. Not fixed in this session (out of scope for agent-provenance).
